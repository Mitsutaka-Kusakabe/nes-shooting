MOJAxMOJA WARS (FC/NES) スプライト・アニメーション・当たり判定オーサリング環境

🚀 エディタを開く 🌌 ステージエディタ

1. 概要と開発目的

「Web キャラクターエディタ」は、ファミリーコンピュータ (NES) の厳格なハードウェア制約（256個のCHRタイル上限、1ライン8スプライト制限、透明1色＋3色のパレット制限）を遵守しながら、自機・敵機・ボスのドット絵グラフィック、アニメーション、当たり判定を直感的に作成・編集・管理できる公式Webオーサリングツールです。

  • 画像ドラッグ＆ドロップ ＆ NES自動減色: 一般のPNGイラストから最適なNES3色＋透明を抽出し、8x8タイルへ自動分解。
  • CHR容量メーター: スプライトCHR（最大256タイル）のリアルタイム消費量を監視し、容量超過を防止。
  • 8スプライト制限警告: 水平スキャンライン上に8枚以上のスプライトが重なったチラつき危険ラインを警告表示。
  • AABB当たり判定（Hitbox/Hurtbox）: キャンバス上で矩形をドラッグ＆リサイズして食らい判定・攻撃判定を設定。
  • デュアルアセンブリ出力: character_data.s (OAM定義) と character_tiles.s (CHRビットマップ) を分離出力。
  • ステージエディタ連携: characters.json を通じてステージマップ上にアニメーションを描画可能。

2. ファミコン実機の仕様とエディタのサポート機能

ハードウェア仕様 実機制約 本エディタの対応機能
スプライト CHR 容量 スプライト用パターンテーブル（バンク0: $0000-$0FFF）に格納できる 8x8 タイルは 最大256個。 ヘッダーの「スプライト CHR メーター」で消費タイル数をリアルタイム表示（75%で黄、超過で赤色警告）。
空タイル除去と同一タイルの重複排除によりCHR消費を最小化。
水平スキャンライン制限 水平1ライン上に同時表示できるスプライトは 最大8枚（64px）。9枚目以降は消滅（チラつき・フリッカー）が発生。 キャンバス左端の「スキャンラインルーラー」に警告インジケータ（赤帯）を表示し、安全なスプライト幅での作画を支援。
スプライトパレット 1スプライトあたり「透明1色 ＋ 任意3色」の全4色のみ使用可能。 画像をドロップするとNESマスター54色から最適な3色を自動抽出。
パレットIDの切り替えによる「パレット色違い複製」にも対応。
OAMメタスプライト 各キャラは複数の 8x8 スプライトを組み合わせて構成（例: 16x16なら4枚）。 各フレームを相対X/Y、タイル番号、属性値のテーブルとして ca65 形式で自動フォーマット。

3. 画像インポートと自動減色・タイル分割

  1. 右パネル上部の「📥 画像インポート ＆ 自動減色」エリアに、手元の PNG、GIF、JPEG 等のドット絵画像をドラッグ＆ドロップします。
  2. アルゴリズムが自動的に以下を実行します:
    • 画像の透明度（アルファ値）を判別し、背景を透過化。
    • ファミコンのマスターパレット（全54色）から、使用頻度の高い 最適な3色 をユークリッド色差で算出してパレットスロットへ自動設定。
    • 画像を 8x8 ピクセルのグリッドに分割。
    • 完全に透明な空タイルを除外 するとともに、全く同じ絵柄のタイルを1つに統合（重複排除） して登録。
  3. 右パネルの「🧩 重複除外後 CHR タイル」に、実際にROMへ焼き込まれる最小化されたタイル群が一覧表示されます。

🤖 画像生成AI（1024×1024px や黒背景JPEG）のスマート自動縮小

ChatGPT / DALL-E、Midjourney、Stable Diffusion 等の画像生成AIで生成したドット絵風画像は、ファイル自体が 1024×1024 px（1ドット＝32px） などの超高解像度かつ 黒背景JPEG で出力されることが大半です。

  • 自動グリッド検出 ＆ 縮小: エディタにそのままドロップするだけで、1ドットの刻み幅（32pxブロック等）を自動判定し、中心ピクセルサンプリングで 32×32 や 16×16 などの正規実機サイズへ自動縮小 します。
  • 黒背景・単色背景の自動透過: アルファチャンネルを持たないJPEG画像であっても、四隅の背景色（黒色など）を自動検出し、余分な外枠を透明化してキャラ本体のみを綺麗に抽出します。

4. アニメーション編集とオニオンスキン

  • アニメーションステートの切り替え: 左パネルのチップから idle（待機）、fly（移動）、attack（攻撃）、damage（被弾）、destroy（撃破・爆発）を選択して、ステートごとに個別のモーションを作成できます。
  • コマ送りタイムライン: 画面下部のタイムラインで「＋ コマ追加」「🗑 コマ削除」を実行してモーションを展開します。
  • コマ持続フレーム（1/60秒単位）: 各コマの持続時間をNES実機フレーム数で指定します（例: 12f ≒ 約0.2秒、6f ≒ 約0.1秒）。
  • オニオンスキン: 前コマのシルエットがキャンバス上に 30% の半透明で表示され、滑らかなアニメーションの中割り調整が容易に行えます。

5. 当たり判定（Hitbox / Hurtbox）の設定

キャンバス上でドラッグ＆リサイズ、または右パネルの数値入力で当たり判定を直接設定できます:

  • 🟦 食らい判定 (Hurtbox): 敵弾や敵機との接触で被弾する有効判定エリア。
  • 🟥 攻撃判定 (Hitbox): 自機弾・近接サーベル・敵の体当たり等、相手にダメージを与える判定エリア。

※ ゲーム本体（src/enemy.s, src/player.s）の衝突判定ルーチンと完全互換を保つため、中心座標からの 半径（Half Width / Half Height） も自動計算されて出力されます。

6. データのエクスポートとプロジェクト適用

💾 characters.json（完全保存＆ステージエディタ連携）

  • ヘッダーの「💾 JSON 保存」をクリックすると、全キャラクター・全アニメーション・当たり判定・パレット設定を包含した characters.json をダウンロードできます。
  • 「📥 JSON 読込」からいつでも保存状態を完全に復元できます。
  • ステージエディタ（docs/editor/）に読み込ませることで、ステージ上の敵やボスをアニメーション表示させることができます。

📤 ca65 ASM 出力（ソースコード化＆実機ビルド）

ヘッダーの「📤 ca65 ASM 出力」をクリックすると、役割の異なる2つのアセンブリコードが生成されます:

タブ・ファイル名 出力内容と役割 適用先ファイル
📄 character_data.s OAMメタスプライト配列（スプライト枚数、相対Y, タイル番号, 属性, 相対X）およびアニメーションフレームテーブル、AABB当たり判定テーブル（Half-W, Half-H）。 src/ 配下のデータファイル
🧩 character_tiles.s 全重複除外タイルをファミコンPPUの 2bpp 形式（16バイト/タイル、Plane 0 + Plane 1）でエンコードした純粋なCHRビットマップ配列。 assets/chr.s または CHR領域
